# 产品需求

DNSLab 是面向开发者、技术支持人员和网络学习者的 DNS 命令行诊断工具。用户指定查询名称和 DNS 服务器，工具展示响应、记录内容与耗时，并支持比较结果和保存报告。

本文说明产品方向。首版交付边界以 [MVP](mvp.md) 为准，当前完成情况见[文档导航](index.md)与[开发计划](todo.md)；产品目标和候选功能不代表已经实现。

## 要解决的问题

- 对同一个名称逐一查询不同服务器时，参数和输出难以保持一致。
- 网络超时、无效报文与 DNS 返回的错误码容易混淆。
- 排查结果需要保留服务器、查询条件和响应证据，方便复查与交流。
- 学习 DNS 协议需要能检查边界、复现错误的实现，而不只是调用已有解析器。

## 用户与场景

| 用户 | 主要场景 |
| --- | --- |
| 开发者 | 查看指定服务器的响应，比较不同解析结果 |
| 技术支持人员 | 保存一次排查的条件和结果，附在问题记录中 |
| 网络学习者 | 理解 DNS 报文、UDP/TCP 传输、截断与超时 |

DNSLab 提供可观察的证据，不根据单次延迟或不同答案直接判定某个服务器错误、被污染或质量较差。

## 产品目标

1. 明确查询对象：由用户显式指定服务器，结果显示实际端点与传输方式。
2. 明确状态：区分传输失败、报文无效与 DNS 响应码，保留失败项的上下文。
3. 方便比较：在相同查询条件下展示不同服务器的结果，不丢弃失败服务器。
4. 便于复查：提供终端输出和结构化报告，记录版本、查询条件与时间。
5. 保持可测试：协议逻辑可以用内存报文测试，网络流程可以用本地模拟服务器复现。

目标平台为 Windows 10/11 x64 和 Linux x86_64；持续集成跟踪 Windows 托管环境以及 Ubuntu、Debian 的最新稳定版和 Arch 滚动版。这是交付目标，实际验证范围以[验证状态](todo.md#验证状态)为准。

## 产品原则

- **输入职责清楚**：查询对象是域名或根名；普通 DNS 使用 IP 端点，DoH 使用 HTTPS 地址，DoT 使用主机或 IP 端点。具体规则见[输入校验](validation.md)。
- **错误分层**：收到有效的 NXDOMAIN、SERVFAIL 或 REFUSED 响应，与未收到有效响应是不同结果。
- **结论有依据**：TTL 和答案差异只是观察结果；缓存、地理调度与传播延迟等原因不能仅凭一次查询确定。
- **等待有界**：每台服务器的查询必须在有限预算内结束；部分收发、无关响应和传输回退不能无限延长等待。
- **保护报告**：输出文件默认不覆盖，覆盖需要明确选项；保存失败必须反馈给调用者。
- **面向脚本**：命令行为、退出码和报告字段保持稳定，报告结构提供版本标识。
- **隐私明确**：不收集遥测、不自动上传报告。实际查询会把名称发送给用户指定的 DNS 服务器，服务器可能记录查询。DoH/DoT 保护到目标服务器的连接；服务器主机名的引导解析可能使用本机配置的普通 DNS。
- **实现范围诚实**：文档区分已实现功能、已确认设计和长期候选，不把局部测试写成全平台支持证明。

## 非目标

- 递归解析器、权威 DNS 服务器、抓包器或完整 DNSSEC 验证器。
- 网站可用性检测、URL 扫描、端口扫描或自动发现网络中的 DNS 服务器。
- 自动修改系统 DNS、Hosts、防火墙或路由。
- 对公共 DNS 服务商进行永久排名，或仅凭短时测量给出故障定论。
- 用图形界面、通用插件系统或高吞吐框架替代首版协议正确性工作。

## 长期候选

以下能力需要分别评估用户价值、实现成本和测试范围，不绑定某个版本，也不构成首版承诺：

- 更多记录类型，以及更完整的 CNAME 链展示。
- 多轮采样、延迟分布、历史报告比较和批量名称输入。
- 可控并发、系统解析器对照模式和更多导出格式。
- Unicode 域名与 IDNA 转换。
- DNSSEC 相关信息、EDNS 扩展状态展示；展示信息不等于完成验证。

候选功能在确认进入开发前，不占用首版命令参数或改变当前默认行为。已确认的接口统一维护在 [CLI 规范](cli.md)。

DoH、DoT 已确认为查询功能，要求严格验证证书和服务器身份，失败时不回退明文；不包含加密服务器比较、自动发现或代理配置。
