# 产品需求

DNSLab 面向开发者、技术支持人员和网络学习者，让用户向指定 DNS 服务器查询域名，查看响应、记录与耗时，并在相同条件下比较多个普通服务器。保存可复查的报告仍是后续目标。

当前命令与后续接口见 [CLI](cli.md)，首版交付范围见 [MVP](mvp.md)。本文描述产品目标，不将规划中的能力视为已经可用。

## 用户与问题

| 用户 | 需要解决的问题 |
| --- | --- |
| 开发者 | 查看指定服务器的响应，区分 DNS 返回码、网络失败和无效报文 |
| 技术支持人员 | 比较不同服务器的结果，保留排查条件与响应证据 |
| 网络学习者 | 理解 DNS 报文、普通与加密传输、截断回退和超时，并离线复现边界情况 |

工具提供观察证据，不根据一次延迟或答案差异直接判定某个服务器错误、被污染或质量较差。

## 产品目标

- **明确查询对象**：由用户显式指定服务器，展示实际目标与传输方式。
- **保留失败上下文**：区分传输失败、报文无效与 DNS 响应码，不丢失已发生的尝试。
- **便于复查**：使用一致的终端输出；后续报告记录版本、查询条件、时间和完整结果。
- **可以验证**：协议逻辑通过内存报文测试，网络流程通过本地模拟服务器复现。

目标平台为 Windows 10/11 x64 和 Linux x86_64。持续集成覆盖 Windows 托管环境，以及 Ubuntu、Debian 最新稳定版和 Arch 滚动版；环境与执行方式见[持续集成](build.md#持续集成)。

## 产品原则

- 查询名称、普通服务器地址与加密服务器地址分别校验，不将输入转换为扫描任务；规则见[输入校验](validation.md)。
- 有效的 NXDOMAIN、SERVFAIL 或 REFUSED 响应与未收到有效响应是不同结果。
- TTL、延迟和答案差异属于观察结果；缓存、地理调度或传播延迟等原因不能仅凭一次查询确定。
- 每次查询等待有界，部分收发、无关响应和传输回退不能无限延长预算。
- DoH/DoT 严格验证证书与服务器身份，失败不回退明文，不提供跳过验证的入口。
- 面向用户的帮助和诊断使用中文，协议标识保留原样；命令与退出码保持稳定。
- 不收集遥测、不自动上传报告。查询名称会发送给用户指定的服务器；加密服务器主机名的引导解析可能使用本机配置的普通 DNS。
- 区分开发完成与平台验收，不把局部测试结果写成全部目标平台均已验证。

## 已确认的后续规划

以下需求仍属于首版交付范围，尚未实现，具体接口集中在 [CLI 后续接口](cli.md#后续接口)：

- **JSON 报告**：保存本次查询或比较的条件与完整结果，提供结构版本；默认拒绝覆盖已有文件，显式允许后才覆盖，保存失败必须反馈错误。

加密服务器比较、自动发现和代理配置不包含在上述规划中。

## 非目标

- 递归解析器、权威服务器、抓包器或完整 DNSSEC 验证器。
- 网站可用性检测、URL 扫描、端口扫描或自动发现 DNS 服务器。
- 自动修改系统 DNS、Hosts、防火墙或路由。
- 对公共 DNS 服务商永久排名，或仅凭短时测量给出故障定论。
- 以图形界面、通用插件系统或高吞吐框架替代首版协议正确性工作。

## 长期候选

以下能力需要另行确认，不绑定版本，也不提前增加命令参数：

- 支持列表以外的记录类型和更完整的 CNAME 链展示。
- 多轮采样、延迟分布、历史报告比较和批量名称输入。
- 可控并发、系统解析器对照和更多导出格式。
- Unicode 域名与 IDNA 转换。
- DNSSEC、EDNS 状态展示；展示信息不等于完成验证。
