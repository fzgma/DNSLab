# 首版范围与验收

首版目标为 v0.1.0：向用户指定的 DNS 服务器发起查询，展示有效响应或失败原因，比较多个服务器，并保存本次结果。

首版尚未交付。当前程序仅提供帮助和版本信息，核心库已实现报文处理、网络基础及单服务器 UDP 查询用例；查询命令、TCP 与回退、比较和报告仍待实现。当前进度见[开发计划](todo.md)，本文列出交付要求。

## 必须交付

| 范围 | 要求 |
| --- | --- |
| 平台 | Windows 10/11 x64、Linux x86_64；持续集成覆盖 Windows 托管环境及 Ubuntu、Debian 最新稳定版和 Arch 滚动版 |
| 查询 | 向显式指定的 IPv4 或 IPv6 DNS 服务器查询 A、AAAA |
| 传输 | UDP、TCP，以及有效截断响应后的 TCP 回退 |
| 响应 | 展示 DNS 响应码、A/AAAA/CNAME、TTL、服务器、传输方式与耗时 |
| 比较 | 对多个不同端点各查询一次，保留每台服务器的独立结果 |
| 输出 | 人类可读的终端结果、带版本信息的 JSON 报告 |
| 错误处理 | 参数错误、超时、网络失败和畸形响应有明确结果 |
| 质量保障 | 单元测试、本地模拟 DNS 集成测试、Windows/Linux 构建与测试流程、使用文档 |

命令、选项、默认值、超时预算、端点去重和退出码只在 [CLI 规范](cli.md) 中定义。域名与服务器输入校验见[输入校验](validation.md)。

## 不属于首版

- MX、NS、TXT、SOA、PTR 等查询类型；展示响应中的 CNAME 不表示支持直接查询 CNAME。
- 多轮采样、延迟百分位、排名、历史数据库和实时监控。
- DoH、DoT、DNSSEC 验证、IDN 自动转换。
- CSV、Markdown 报告和图形界面。
- 自动递归追踪 CNAME、权威服务器发现或根服务器迭代查询。

后续方向见[产品需求](prd.md)，不为尚未确认的功能提前增加命令选项。

## 响应与输出交付

### 终端结果

每台服务器展示查询名称与类型、实际服务器端点、使用的传输、耗时、传输状态和 DNS 响应码。有回答时展示记录名称、类型、TTL 与可读值；保留记录所在 section，不能把附加记录误当作直接答案。

- 有效的 NXDOMAIN、SERVFAIL、REFUSED 等响应仍属于传输成功。
- 常见响应码显示名称，未知响应码保留数值。
- NOERROR 但没有目标类型的直接答案，应明确展示这一状态，不直接宣告名称不存在。
- 回退发生时展示 UDP 截断与 TCP 最终结果。
- 比较模式展示各服务器的结果与差异，不直接判断哪个答案正确或哪个服务器最好。
- 不支持解码的记录至少保留类型编号和 RDATA 长度，不误解析为支持的类型。

### JSON 报告

报告包含本次所有服务器的结果，包括失败项。顶层最少包含：

| 字段 | 内容 |
| --- | --- |
| `schema_version`、`tool_version` | 报告结构版本与程序版本 |
| `started_at`、`duration_ms` | 含时区的 RFC 3339 开始时间、总耗时 |
| `query` | 查询名称与类型 |
| `options` | 本次使用的超时和传输选项 |
| `results` | 每个服务器一项的完整结果 |

每项结果最少包含 `server`、`transport_used`、`elapsed_ms`、`transport_status`、`rcode`、`flags`、`answers` 和 `error`。未收到有效响应时，`rcode` 与 `elapsed_ms` 为 `null`；没有错误时 `error` 为 `null`。

`transport_status` 使用稳定枚举，区分成功、超时、连接拒绝、收发失败和无效响应。`flags` 至少保留 `tc`、`aa`、`ra`、`ad`、`cd`；答案保留名称、类型、TTL 与值。UDP 截断和 TCP 回退过程必须可追溯。

报告实现时提交 JSON Schema 和相应测试。发布后的字段与含义保持兼容，破坏性调整提高 `schema_version`；具体写入和覆盖行为见 [CLI 规范](cli.md)。

## 协议与实现要求

- 自行实现 DNS 报文构造与解析，不用现成 DNS 客户端库替代协议核心。
- 请求使用事务 ID，响应校验事务 ID、QR、Question；UDP 同时校验来源端点。不匹配的数据不能作为本次成功结果。
- 名称、压缩指针、字段长度和计数全部受边界检查约束，畸形输入不能导致越界或无限循环。
- TCP 按两字节长度前缀处理完整 DNS 消息，支持部分发送与部分读取。
- A 和 AAAA 的数据长度必须分别为 4 和 16 字节；CNAME 使用同一名称解码器。原始标签字节与用户输入规则分开处理。
- 网络等待和回退遵守 [CLI 规范](cli.md) 的每台服务器总预算。
- 使用 C++23 与 CMake，保持协议逻辑、网络、结果模型和输出分层，细节见[架构](architecture.md)与[报文编解码](wire-codec.md)。

## 验收

首版完成前，应全部满足以下条件；当前已完成项由[开发计划](todo.md)维护，不在本文重复记录每次测试数字。

- [ ] 目标 Windows 与 Linux 环境均可按[构建说明](build.md)配置、构建和测试，实际验证环境有记录。
- [ ] CLI 的帮助、版本、全部选项、输入校验与退出码符合 [CLI 规范](cli.md)；非法输入在网络请求前被拒绝。
- [ ] IPv4 与 IPv6 本地模拟服务器均能完成 A、AAAA 查询，CNAME 与后续回答展示正确。
- [ ] NXDOMAIN、SERVFAIL、REFUSED 与超时、连接失败、无效响应得到不同状态。
- [ ] UDP、显式 TCP、有效 TC 响应后的回退均可运行，UDP 超时不会自行切换 TCP。
- [ ] TCP 分段收发、回退和不匹配响应均不重置总预算，查询在预算内结束。
- [ ] 比较模式保留每个不同端点的结果，一台服务器失败不影响其余服务器完成查询。
- [ ] JSON 通过 Schema 校验，失败项完整保留，终端输出与报告状态一致，文件覆盖符合约定。
- [ ] 短报文、长度错误、计数不符、压缩循环与指针越界等夹具安全失败。
- [ ] 核心单元与集成测试全部离线运行，不以公共 DNS 可用性作为通过条件。
- [ ] 使用文档说明当前能力、构建方法、输入要求、退出码、报告和隐私边界。

本地集成测试至少覆盖正常响应、DNS 错误码、无响应、来源或事务信息不匹配、TC 回退成功与失败、TCP 分段传输，以及比较模式中的局部失败。公开网络上的手工检查不能替代这些测试。
