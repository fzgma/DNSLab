# 代码与提交风格

本文约定自有代码的说明、输出方式和提交文案。命令含义以 [CLI](cli.md) 为准，模块边界以[架构](architecture.md)为准，构建要求见[构建说明](build.md)。

## 中文说明

- 帮助、查询结果、参数错误、运行错误、构建诊断和自有测试说明使用中文。
- 命令与选项、协议缩写、记录类型、响应码、代码标识符和测试机器标签保持稳定，不因界面中文化改名。
- 注释说明用途、边界、资源所有权或选择原因。复杂的平台分支、长度检查、超时预算、TLS 生命周期和测试时序应解释关键约束。
- 第三方依赖及生成文件不在仓库内改写；自有程序通过边界层提供中文提示，不直接把第三方英文异常作为完整用户错误。

## 函数说明

每个自有函数、构造与析构、成员接口、内部辅助函数均写一句中文说明，交代它完成什么或保证什么。C++ 使用 `///`，Python 使用函数文档字符串，CMake 函数与宏使用紧邻定义的 `#` 注释。公开声明与实现分别保留读者需要的说明；默认和禁止的成员操作也说明所有权意图。

复杂匿名函数在就近位置说明用途。测试框架生成的测试函数以中文案例名称描述验证目标，无需再重复相同注释；测试辅助函数仍按普通函数处理。

## C++23

- 自有 C++ 输出统一通过 `std::print` / `std::println` 完成，使用 `stdout` / `stderr` 区分通道。
- 需要先构造文本时使用 `std::format`，不再通过 `std::cout`、`std::cerr` 或字符串流拼接终端输出。
- 可恢复错误继续使用 `std::expected`；连续数据使用 `std::span`，资源遵守 RAII 和明确的移动所有权。
- 重构时保持协议处理、错误类别、退出码及预算语义稳定，行为变更另行说明和验证。

修改面向用户的文字后，同步帮助与端到端测试，核对中文终端、重定向输出及 Windows 中文路径。构建阶段检查标准库实际能否编译和链接所用功能，不只检查编译器版本。

## 提交文案

- 标题使用 Angular 格式：`type(scope): 中文概述`，范围可省略；类型使用 `feat`、`fix`、`docs`、`refactor`、`test`、`build`、`chore` 等约定标记。
- 固定三段，段落之间空一行：第一段为标题，第二段描述主要改动，第三段描述配套改动或具体行为调整。
- 概述与正文使用中文，只描述本次实际改动；少用技术词，必要的命令和选项名称保留原样。
- 不写工作过程、测试结果、验收数字、讨论经过、未来计划或宣传性评价，不为凑段落编造改动。
