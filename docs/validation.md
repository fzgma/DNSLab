# 输入校验

本文统一定义查询名称、服务器地址和超时输入的规则。命令与选项见 [cli.md](cli.md)，网络报文中的名称处理见 [wire-codec.md](wire-codec.md)。名称、端点和超时值的校验已在核心库实现；命令组合校验随查询命令接入。

## 参考与适用范围

规则参考 scan 项目 `utils/net.py` 中 `is_valid_host` 的域名分支，以及对空白、控制字符和非 ASCII 符号的检查。DNSLab 输入是 DNS 查询名称，不是 URL；IP 地址用于服务器选项。

参考函数会先尝试解析 IP，并接受符合其地址范围限制的有效 IP；仅在 IP 解析失败后才执行域名分支。DNSLab 拒绝把 IP 用作查询名称，是依据查询名与服务器地址职责做的适配，不是参考函数整体的行为。

| 参考行为 | DNSLab 的处理 |
| --- | --- |
| 标签使用字母、数字、内部连字符 | 沿用，首尾必须是 ASCII 字母或数字 |
| 标签最多 63 字节、普通域名文本最多 253 字节 | 沿用；以完整名称的 255 字节编码上限统一校验 |
| 拒绝只含数字和点的域名候选 | 沿用；查询名称不接受合法或无效的 IP 形式 |
| IP 地址验证与地址范围判断 | 属于独立的服务器地址职责，不用于名称编解码 |
| URL 补全、协议选择、去除首尾空白与 HTTP 请求 | 不采用，输入原样校验 |
| 参考函数的域名分支拒绝尾点产生的空标签 | DNS 查询保留根名称 `.` 和可选的单个尾点 |

外部 Python 文件仅作为规则参考，不是构建或运行依赖；测试不导入它，也不执行其中的网络请求。

## 查询名称

`parse_ascii_name` 返回由原始标签组成的名称，并保留大小写。

- 空字符串无效；单独的 `.` 表示根名称。
- 普通名称以半角点分隔，允许一个可选尾点。禁止开头空标签、中间空标签和多个尾点。
- 每个标签为 1–63 字节，字符仅限 `A–Z`、`a–z`、`0–9` 和内部的 `-`；标签首尾不能是连字符。
- 完整编码不得超过 255 字节，包含每个标签的长度字节及最后的根终止字节。普通文本不含尾点时最多 253 字节，含可选尾点时最多 254 字节。
- 常规字符与长度校验成功后，仍拒绝仅由数字和点组成的名称。`123.example`、`example.123` 和 `1-2` 不属于这种输入。
- 接受用户已经转换的 Punycode 标签；不进行 Unicode 转码，也不检查其对应站点是否存在。
- 拒绝空白、控制字符、零宽字符、非 ASCII 字符、全角符号、下划线和反斜线转义。字符错误使用原始输入的字节偏移；每个标签的空值与长度检查先于该标签的字符检查。
- 不去除空白、不补协议、不提取 URL 中的主机、不自动把 IP 改为反向查询。

| 输入 | 结果 |
| --- | --- |
| `Example.COM`、`example.com.` | 接受，保留大小写 |
| `.`、`localhost`、`xn--bcher-kva.example` | 接受 |
| `123.example`、`a.123`、`1-2` | 接受 |
| `123`、`123.`、`1.2.3`、`192.0.2.1`、`999.1.1.1` | 拒绝纯数字名称或 IP 形式 |
| `.example`、`a..b`、`example.com..` | 拒绝空标签 |
| `-example.com`、`example-.com` | 拒绝标签边界连字符 |
| `https://example.com`、`example.com:53`、`user@example.com` | 拒绝 URL、端口或凭据语法 |
| `::1`、`[::1]` | 拒绝 IP 形式；服务器地址有独立入口 |
| `例子.com`、`example．com`、带空格或零宽字符的名称 | 拒绝非 ASCII 或不可见字符 |

名称校验只检查输入形式，不验证注册状态、公共后缀或网络可达性。

## 名称错误

错误包含 `code` 与原始输入的字节 `offset`，不在核心层拼接用户提示。

| 错误 | 位置 |
| --- | --- |
| `EmptyName` | 0 |
| `EmptyLabel` | 空标签起点 |
| `LabelTooLong` | 过长标签起点 |
| `NameTooLong` | 使完整名称超长的标签起点 |
| `InvalidCharacter` | 非法字节 |
| `HyphenAtBoundary` | 标签首尾连字符 |
| `NumericOnlyName` | 0；仅在其余校验通过后返回 |

## 服务器地址

`parse_endpoint` 已实现下列服务器地址规则；`--server` 尚未接入程序：

- 必须显式提供 IPv4 或 IPv6 字面地址，不接受主机名，不调用系统 DNS 解析服务器名称。
- 接受 IPv4、`IPv4:port`、裸 IPv6 和 `[IPv6]:port`。裸 IPv6 整体作为地址解释，不能猜测最后一段为端口。
- IPv4 必须是四段十进制，每段为 0–255，多位段不能以 0 开头；IPv6 支持压缩和 IPv4 尾部形式，其中 IPv4 尾部遵循相同规则。
- 默认端口为 53，显式端口必须是 1–65535 的 ASCII 十进制整数，可以有前导零，不能有正负号、小数或空白。
- 不接受无端口的 `[IPv6]`、IPv4 方括号、IPv6 区域标识（如 `%eth0`、`%3`），也不接受 URL、首尾空白、控制字符、NUL 或非 ASCII 字符。
- 地址解析并规范化后，以 IP 与端口组合判断重复；重复端点报参数错误，不静默删除。`1.1.1.1` 与 `1.1.1.1:53` 相同，`::1` 与 `[0:0:0:0:0:0:0:1]:53` 相同。
- 相等判断使用地址族、地址字节和端口；IPv4 与映射到 IPv6 的地址保留不同地址族，不合并为同一端点。
- 同一 IP 的不同端口属于不同端点。查询与比较对端点数量的要求由 [cli.md](cli.md) 定义。
- `net.py` 中的地址范围限制不自动成为 DNSLab 的服务器策略。当前只校验地址形式，不根据是否为未指定地址、广播或组播地址实施访问控制，也不检查可达性。

`format_endpoint` 始终显示端口；IPv6 使用方括号、小写十六进制，并压缩最长且至少含两个零段的连续区间，长度相同时选择最左区间。IPv4 尾部形式统一显示为十六进制段，例如 `::ffff:192.0.2.1` 显示为 `[::ffff:c000:201]:53`。重复判断不依赖显示文本。

### 端点错误

`EndpointInputError` 包含 `code` 与原始输入字节 `offset`。先检查整个输入中的非法字符，再检查结构、地址和端口。

| 错误 | 位置 |
| --- | --- |
| `EmptyInput` | 0 |
| `InvalidCharacter` | 非法字符的首字节 |
| `InvalidFormat` | 不符合地址与端口组合形式的位置 |
| `InvalidAddress` | 地址起点；裸地址为 0，方括号内为 1 |
| `MissingPort` | 缺失端口应开始的位置 |
| `InvalidPort` | 端口中的非数字字节 |
| `PortOutOfRange` | 端口起点 |
| `DuplicateEndpoint` | 0；由端点列表校验返回 |

`parse_unique_endpoints` 保持输入顺序，返回首个输入错误或重复错误。列表错误还包含 `input_index`；重复错误的 `first_duplicate_index` 指向最早相同端点，其他错误该字段为空。列表函数本身允许空列表，命令所需的端点数量由命令行层校验。

## 超时输入

`parse_timeout_ms` 按 [cli.md](cli.md#选项) 的范围校验超时值，返回毫秒数。仅接受 ASCII 十进制数字，可有前导零；不去除空白，不接受正负号、小数、NUL 或非 ASCII 字符。先检查整个输入的字符，再判断数值范围，超长数字也不能导致整数溢出。

`TimeoutInputError` 包含 `code` 和原始字节 `offset`：`EmptyValue`、`OutOfRange` 的位置为 0，`InvalidCharacter` 定位首个非法字节。截止时间的使用和边界见 [network.md](network.md#查询预算)。

## 报文名称与显示

服务器返回的名称标签允许任意字节，不能套用查询输入的字符或纯数字限制。编码器独立验证空标签、标签长度和完整名称长度；解码器保留数据并检查报文边界与压缩循环。

名称比较仅将 ASCII 大写字母折叠为小写，其他字节与标签边界精确比较。显示保留原始大小写并补尾点；控制字节、非 ASCII 字节、空格、标签内的点和反斜线使用反斜线加三位十进制数字转义。显示结果不承诺能由受限的输入函数重新读取。
